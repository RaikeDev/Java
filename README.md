# ООП в задачах на Java

Решения задач из учебного пособия «Объектно-ориентированное программирование в задачах на языке Java» (А. В. Ермаков, версия 1.4).

Задачи в пособии сквозные: одни и те же сущности (`Point`, `Line`, `Fraction`, `Student` и другие) переходят из блока в блок и дополняются новыми требованиями. Репозиторий отражает этот путь: от классов с одним полем до обобщённых типов, шаблонов проектирования и внедрения зависимостей.

Пособие рассчитано на тех, кто знает процедурное программирование (переменные, циклы, условия, функции, массивы) и осваивает объектно-ориентированный подход.

## Сквозные сущности

Одни и те же классы развиваются на протяжении всего курса:

```text
Point    (1.1.1) -> Point (1.4.1, конструктор) -> ThreeDPoint (2.1.5) -> Point (5.2.2, clone)
Line     (1.2.1) -> Line (1.4.2, конструкторы) -> Line (1.5.3, длина) -> Line (5.1.3, equals) -> Line (6.1.5, обобщения)
Fraction (1.5.5) -> Fraction (1.6.4, инкапсуляция) -> Fraction (2.2.2, Number) -> Fraction (7.1.2, фабрика)
Student  (1.3.1) -> ... -> Student (4.1.1, исключения) -> Student (6.1.4, Comparable) -> Student (7.3.4, отмена действий)
```

Новые требования заставляют пересматривать архитектуру и применять новые возможности языка.

## Требования

- JDK 17 или новее. Запечатанные классы (`sealed`), которые используются с блока 2.1, стали стабильной возможностью языка именно в 17-й версии.
- Для главы 9 нужна зависимость `spring-context` (подключается через Maven или Gradle).

## Структура проекта

```text
src/
├── Main.java            // точка входа, вызов тестовых методов
├── MainTest.java        // task1_1_1, task1_5_5, ...
├── geometry/
│   ├── Point.java
│   ├── Line.java
│   ├── PolygonalLine.java
│   └── Square.java
├── fraction/
│   └── Fraction.java
└── student/
    └── Student.java
```

- Каждый публичный класс лежит в отдельном файле.
- Тестовые методы вида `task1_5_5()` находятся в классе `MainTest`, точка входа `main` — в классе `Main`.
- Порядок работы над задачей: сначала реализуется сущность по первой части задания, затем её корректность проверяется тестовыми методами из второй части.

## Запуск

Откройте проект в IntelliJ IDEA, Eclipse или VS Code и запустите `Main`. Либо из командной строки (Linux, macOS, Git Bash):

```bash
git clone https://github.com/RaikeDev/Java.git
cd Java
javac -d out $(find src -name "*.java")
java -cp out Main
```

Эти команды подходят для глав 1–8. Главу 9 собирайте через Maven или Gradle, чтобы подтянуть Spring.

## Основные принципы

- **Инкапсуляция состояния.** Поля объявляются `private`, доступ к ним идёт через конструкторы, геттеры и сеттеры с проверками.
- **Инкапсуляция реализации.** Интерфейс класса остаётся неизменным, внутреннее устройство может меняться.
- **IS-A и HAS-A.** Наследование применяется только там, где есть настоящая иерархия, в остальных случаях используется композиция.
- **Слабая связанность.** Предпочтение отдаётся ссылкам на интерфейсы и внедрению зависимостей.
- **Контракты `equals` и `hashCode`.** Рефлексивность, симметричность, транзитивность, согласованность, а также согласованность `hashCode` с `equals`.
